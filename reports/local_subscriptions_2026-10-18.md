# Проверка личных подписок на локальном host — 2026-10-18

Проверка выполнена на этой машине, не на globe. Исходный `subscriptions.txt`
перенесён из репозитория в приватный каталог пользователя с правами `0700`;
сам файл и производные конфиги имеют права `0600`. URL, URI, ключи и содержимое
подписок в отчёт не включены.

## Охват

| Источник | Формат | Найдено узлов | Принято | Пропущено валидатором |
|---|---|---:|---:|---:|
| batch1 | base64 VLESS | 62 | 62 | 0 |

| batch3 | base64 VLESS | 37 | 37 | 0 |
| batch4 | одиночный VLESS URI | 1 | 1 | 0 |

Все четыре нормализованных конфига прошли `mihomo -t` v1.19.32. В клиентский
профиль импортировано 405 proxy маршрутов; вместе с `direct` каталог содержит
406. Двенадцать узлов batch2 отклонены из-за непубличных либо неразрешимых
адресов согласно действующей проверке `personal.validate_yaml`.

Установлен локальный backend Docker Compose и host TUN helper. Оба контейнера
стали healthy; `egressctl doctor` подтвердил конфигурацию, control plane,
идентичность и proxy endpoint. Для рабочего SS маршрута подтверждены HTTP 204
через `egress-run` и через TUN, DNS и UDP/QUIC. Параллельные TUN и one-shot
задания сохраняют изоляцию. `direct` работает в обоих режимах. Личный каталог
host пользователя не появляется в отдельном профиле `host-main`.

Проверялись отдельные реальные узлы, а не доступность каждого из 405.
Первый выборочный тест VLESS/Trojan/Hysteria2/VMess дал сетевые ошибки TLS/EOF;
он не доказывает неисправность всей подписки. Среди первых 16 проверенных SS
узлов batch2 семь получили `healthy=true` и подтвердили HTTP 204. Доступность
узлов зависит от времени, целевого сайта и состояния провайдера.

## Найденные дефекты и исправления

| Область | Проявление | Причина и исправление |
|---|---|---|
| Установка backend | Запуск installer из чужого текущего каталога ломался на шаге Compose | Скрипт теперь переходит в корень репозитория перед `docker compose` и добавляет `/usr/local/bin` в PATH для acceptance. Добавлен сценарий запуска вне репозитория. |
| Установка клиента | Повторная host установка лишала service UID доступа к backend secrets | `/etc/vibelab-egress` получает `0755` для прохода к собственным закрытым файлам service UID. Повторная установка и `whoami` проверены live. |
| Безопасный импорт URL | URL подписки попадал в argv процесса при `source add --url` | Добавлен ввод `--url -` из stdin; реальные URL не попали в историю shell. |
| Live harness: большой каталог | JSON `list`, `probe-domain`, `best` обрезался на 8 КБ и не разбирался | Для этих ответов снято ограничение вывода. |
| Live harness: proxy/IP | Проверки proxy использовали `urllib` без SOCKS и сравнивали меняющийся публичный IP | Проверки proxy теперь используют SOCKS-aware `curl` с HTTP 204; прямой маршрут проверяется на публичный адрес и отсутствие TUN без точного равенства IP. |
| Live harness: отсутствующий OpenScience | Проверка отсутствующего контейнера давала fail | При отсутствии контейнера фиксируется явный skip. |
| CLI: долгие сетевые операции | `probe-domain --all`, `best --domain`, benchmark обрывались после 15 секунд | Для этих команд задано ожидание 150 секунд; сообщение тайм-аута больше не советует `source list` для несвязанных команд. |
| CLI benchmark | `benchmark ROUTE --bytes 1M` игнорировал размер | Параметр передаётся в API; добавлен регрессионный тест. |
| Backend probe | TLS handshake timeout одного узла приводил к HTTP 500 всего запроса | Timeout классифицируется как `tls_failure` данного узла. Добавлен тест с зависшим TLS handshake. |
| Backend benchmark | SOCKS запрос строился к host `http` из некорректно разобранного URL; объём включал HTTP заголовки | URL разбирается как HTTP адрес, установлен рабочий ограниченный endpoint; учитываются только байты тела, проверяется HTTP status и полнота загрузки. |

## Приёмка и ограничения

Локальный офлайн-набор: **373 теста пройдено**; сценарии установки:
**75 пройдено**. Отдельная root-проверка host TUN: **18 pass, 0 fail, 4 skip**.
Root live acceptance: **17 pass, 0 fail, 11 skip**; у `host-main` нет личных
подписок, поэтому provider-зависимые проверки пропущены. Отчёты сохранены
в закрытых каталогах host и пользователя; исходный globe-отчёт не изменён.

Финальный пользовательский live acceptance: **23 pass, 0 fail, 5 skip**.
Независимый `verify-live-report.py` подтвердил hash, все 23 pass и отсутствие
секретов в отчёте. Массовый domain probe обработал 50 маршрутов: 12 `ok`,
38 `tls_failure`; `best --domain` вернул 22 ранжированных кандидата.
Benchmark рабочего SS маршрута скачал ровно 1 MiB за 2,3 с. В конце прогона
оба контейнера оставались healthy.
Полный JSON отчёт пользователя находится в
`~/.local/share/vibelab-egress-test/live-user-finalfull.json` с правами `0600`.

Полный пользовательский прогон включает 28 checks. OpenScience-зависимые
проверки помечаются skip, поскольку на этой машине нет контейнера OpenScience;
проверка его перезапуска дополнительно выключена по умолчанию. Host harness
требует root и проверен отдельно. Проверка одинакового release клиента между
host и OpenScience также неприменима без контейнера.

`probe-domain --all` по текущему лимиту backend охватывает первые 50 маршрутов
из 406 за один запрос. Это ограничение ресурса, а не свидетельство проверки
каждого узла. Рабочие узлы других провайдеров подтверждены отдельными
`egressctl test`, `egress-run` и TUN заданиями.
